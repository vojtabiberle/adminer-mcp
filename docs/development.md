# Development and testing

## Environment

- Python 3.12+ through `uv` (`uv sync`, `uv run …`).
- Run the server: `uv run adminer-mcp`; debug with MCP Inspector: `npx @modelcontextprotocol/inspector uv run adminer-mcp`.
- Lint and format: `ruff`; types: `mypy --strict` on `src/`.

## Test environment: Adminer in Docker

Tests never run against the production Adminer. `docker/compose.yml` starts:

| Service | Image | Purpose |
|---|---|---|
| `adminer` | `php:8.4-apache` with the `pgsql` extension and a mounted `adminer-6.3.1.php` (downloaded from the GitHub release, SHA-256 checked in the repository) | Same version as on the server |
| `postgres` | `postgres:17` | Test database with a seed script |

Why not the official `adminer` image from Docker Hub: the version must match the server exactly (6.3.1), and the image may not have a current tag. A custom PHP image with a pinned file gives control over the version. When the server version changes, update the file and its checksum.

The seed (`docker/postgres/init.sql`) contains the cases the parser must handle: NULL vs. empty string, multi-line text, HTML characters (`<i>NULL</i>` as text), Unicode, JSON/JSONB, `bytea`, high-precision `numeric`, time zones, arrays, a table with more than 1000 rows, two schemas, two databases, a read-only user and a user with write access.

## Test layers

| Layer | What | How to run |
|---|---|---|
| Unit – parser | Saved HTML responses in `tests/fixtures/adminer-6.3.1/` → expected `StatementResult` | `uv run pytest tests/unit` |
| Unit – safety | Table of SQL → category and decision (see [sql-safety.md](sql-safety.md#tests)) | same |
| Unit – config | Profile loading, driver aliases, missing password, collisions | same |
| Integration | Full tools against Adminer in Docker: login, relogin after the session is deleted, wrong password (one attempt), CSRF, all tools, policy | `uv run pytest tests/integration` (needs `docker compose up`) |

Fixtures are generated by the script `tests/fixtures/record.py` against the Docker environment. They are never copied from production, because they would contain data. Each item of the [markup checklist](adminer-protocol.md#parser-markup-dependencies-checklist-for-version-changes) must have at least one fixture.

The brute-force block test does not run by default (it needs 30 failed logins). It is marked `@pytest.mark.slow`.

## New Adminer version

1. Go through an RFC if behavior changes; otherwise a PR is enough.
2. Update the file and the checksum in `docker/`, regenerate fixtures, review the diff.
3. Check the [markup checklist](adminer-protocol.md#parser-markup-dependencies-checklist-for-version-changes) against the diff of the Adminer sources (`git diff v6.3.1..vX -- adminer/sql.inc.php adminer/include/auth.inc.php …`).
4. Add the version to the list of tested versions.

## New driver

1. PRD (why, priority), and an RFC for drivers without SQL.
2. `dialects/<driver>.py` with metadata SQL and the list of functions with side effects.
3. A service in `docker/compose.yml`, seed and fixtures, extended integration tests.
4. Update [configuration.md](configuration.md) (supported drivers) and [tools.md](tools.md) if outputs differ.
