# Development and testing

## Environment

- Python 3.12+ through `uv` (`uv sync`, `uv run …`).
- Run the server: `uv run adminer-mcp`; debug with MCP Inspector: `npx @modelcontextprotocol/inspector uv run adminer-mcp`.
- Checks (all must pass before a commit):

  ```bash
  uv run ruff format --check src tests
  uv run ruff check src tests
  uv run mypy src tests          # strict
  uv run pytest                  # unit tests; integration tests run if Docker is up
  ```

## Test environment: Adminer in Docker

Tests never run against the production Adminer. `docker/compose.yml` starts:

| Service | Image | Purpose |
|---|---|---|
| `adminer` | `docker/adminer/Dockerfile`: `php:8.4-apache` with the `pgsql` extension and `adminer-6.3.1.php` downloaded from the GitHub release and checked by SHA-256 | Same version as on the server, at `http://127.0.0.1:8088/adminer.php` |
| `postgres` | `postgres:17` | Test database with a seed script, reachable only from the Adminer container |

```bash
docker compose -f docker/compose.yml up -d --build --wait
docker compose -f docker/compose.yml down -v      # remove, including the data
```

Why not the official `adminer` image from Docker Hub: the version must match the server exactly (6.3.1), and the image may not have a current tag. When the server version changes, update `ADMINER_VERSION` and `ADMINER_SHA256` in the Dockerfile.

The seed (`docker/postgres/init.sql`) contains the cases the parser must handle: NULL vs. empty string, multi-line text, HTML characters (`<i>NULL</i>` as text), Unicode, JSON/JSONB, `bytea` (UTF-8 and not), high-precision `numeric`, `char`, time zones, arrays, links (e-mail, URL), a table with 1,500 rows, a view, two schemas, two databases, a function that writes (for the read-only guard), and the roles:

| User | Password | Rights |
|---|---|---|
| `reader` | `reader-test-pw` | `SELECT` |
| `writer` | `writer-test-pw` | `SELECT`, `INSERT`, `UPDATE`, `DELETE` |
| `postgres` | `postgres-test-pw` | superuser (DDL tests) |

The integration tests change data (they insert into `audit.log`). Recreate the environment with `down -v` for a clean state.

## Test layers

| Layer | What | How to run |
|---|---|---|
| Unit – parser | Saved HTML responses in `tests/fixtures/adminer-6.3.1/` → expected results | `uv run pytest tests/unit` |
| Unit – client | Login, relogin, CSRF retry, no retry after a failed login, lockout, logout, URL parameters – with `httpx.MockTransport` and the fixtures | same |
| Unit – safety | Table of SQL → category and decision (see [sql-safety.md](sql-safety.md#tests)) | same |
| Unit – config, dialects | Profile loading and validation, keyring, quoting in metadata SQL | same |
| Integration | All tools against Adminer in Docker, through `AdminerService` and through an in-process MCP client; logout on shutdown | `uv run pytest tests/integration` (skipped if Adminer is not reachable) |

Fixtures are generated by `uv run python tests/fixtures/record.py` against the Docker environment. It uses plain httpx, so the fixtures do not depend on the client under test. Never copy fixtures from production: they would contain data. Each item of the [markup checklist](adminer-protocol.md#parser-markup-dependencies-checklist-for-version-changes) has at least one fixture.

Not covered by automated tests: HTTP Basic auth in front of Adminer, the keyring with a real backend (`set-password`), the brute-force lockout of a real Adminer (needs 30 failed logins; the parser and client handle it from a modified fixture), and SIGTERM handling of the stdio process (checked by hand).

## New Adminer version

1. Go through an RFC if behavior changes; otherwise a PR is enough.
2. Update the version and the checksum in `docker/adminer/Dockerfile`, rebuild, run `tests/fixtures/record.py` into a new `tests/fixtures/adminer-X/` directory and review the diff.
3. Check the [markup checklist](adminer-protocol.md#parser-markup-dependencies-checklist-for-version-changes) against the diff of the Adminer sources (`git diff v6.3.1..vX -- adminer/sql.inc.php adminer/include/auth.inc.php adminer/include/connect.inc.php …`).
4. Add the version to `TESTED_VERSIONS` in `client.py`.

## New driver

1. PRD (why, priority), and an RFC for drivers without SQL.
2. `dialects/<driver>.py` with metadata SQL, the function lists and the transaction properties; register it in `dialects/__init__.py`.
3. A service in `docker/compose.yml` (and the PHP extension in the Adminer image), seed and fixtures, extended integration tests.
4. Update [configuration.md](configuration.md) (supported drivers) and [tools.md](tools.md) if outputs differ.
